# 관제 운영 절차(Runbook)

관제원이 이 시스템으로 한 교대를 운영할 때 따르는 절차입니다. 상황별 흐름은 채용 공고에 나온 운영 조직의 공통 흐름(원격 모니터링 → 1차 조치·보고 → 개발·현장 지원 요청 → 정상화 확인·인수인계)과 상용 FMS 문서의 대처 방식을 따릅니다. 근거는 [research/02_jobs_and_incident_response.md](research/02_jobs_and_incident_response.md)(R2)의 B-1·B-3입니다. 모든 알람의 자동 조치·절차·명령 버튼은 `fleet/alarms.py`에 정의되어 있고, 화면 알람 대기열에서 알람을 펼치면 같은 내용이 체크리스트로 보입니다.

## 1. 교대 흐름

| 시점 | 할 일 | 화면 |
|---|---|---|
| 교대 시작 | 이전 교대의 인수인계 메모와 현재 상황 요약 확인 | 이벤트·감사 탭 → "현재 상황 요약 받기" |
| 시작 점검 | 통신 두절·고장·원격 조종·일시정지 차량, 봉쇄 구역, 설비(고속문) 상태, 인프라 감지 연결 확인 | 상단 리본, 차량 목록(예외 우선 정렬), 구역 제어 탭 |
| 근무 중 | 알람 대기열을 우선순위 순서로 처리, 조치는 SOP 버튼으로 실행(감사 로그에 남음) | 알람 대기열, 지도 |
| 사고 발생 | 사고 기록(전 30초·후 10초)을 재생해 경위 확인, 보고서 작성 | 사고 기록·재생 탭 |
| 교대 종료 | 조치 중인 사항·주의 구역·다음 교대 요청을 메모로 남김. 시스템이 알람·고장·봉쇄·교착·지표를 자동 요약해 같이 저장 | 이벤트·감사 탭 → "인수인계 기록" |

## 2. 알람 처리 원칙

| 우선순위 | 응답 | 예 | 보류 |
|---|---|---|---|
| 1 긴급 | 즉시 | 사람 접촉, 충돌, 관제 비상정지, 점유-예약 불일치, 교착 자동 해소 실패 | 불가 |
| 2 높음 | 5분 안 | 로봇 고장, 위치 상실, 통신 두절, 인프라 감지 두절, 설비 이상, 대치, 배터리 위험, 장시간 정지, 알람 홍수 | 사유와 만료(10·30·60분)를 적어 보류 가능 |
| 3 보통 | 30분 안 | 혼잡, 작업 지연, 봉쇄 구역 대기, 충전기 부족 | 〃 |
| 4 알림 | 사후 검토 | 근접사고 | 확인 불필요, 알람률에서 제외 |

- 확인(ACK)은 "봤고 책임진다"는 뜻입니다. 조치 완료가 아닙니다. 조건이 사라져도 확인하지 않은 알람은 "정상 복귀·미확인"으로 남습니다.
- 알람 홍수(10분에 10건 초과)가 뜨면 1순위부터 처리하고, 같은 원인의 알람은 묶어 판단합니다. 원인 구역을 일시정지해 신규 알람을 줄입니다.
- 파생 알람은 시스템이 억제합니다. 고장 차량이나 고장 난 문 뒤에서 기다리는 차량은 따로 알람을 올리지 않으므로, 원인 알람을 먼저 처리합니다.

## 3. 상황별 대응

R2 B-1의 표 형식(감지 → 1차 자동 → 관제원 → 현장 → 재개 조건 → 기록)입니다.

| 상황 | 감지 | 1차 자동 대응 | 관제원 조치 | 현장 조치 | 재개 조건 | 기록 |
|---|---|---|---|---|---|---|
| 보호정지(사람·물체) | 차량 state `x_safetyField` PROTECTIVE | 차량이 즉시 정지 | 원인 유닛 확인. 20초 넘게 이어지면 STANDOFF 알람: 지게차면 무전으로 양보 요청, 사람이면 현장 안내, 공간이 있으면 원격 조종으로 후진 | 물체 제거 | 필드가 2초 비면 자동 재개 | 보호정지 횟수·위치(혼잡 레이어), 20초 초과 시 알람 이력 |
| 사람 접촉 | 범퍼 + 접촉 판정 | 해당 차량 범퍼 정지, 반경 6 m 차량 일시정지 | 부상 확인 최우선, 구역 봉쇄, 차량 수동 모드로 격리 | 부상 대응, 현장 통제 | 안전 담당 확인 → 현장 조치 완료 → 주변 재개 | 사고 기록 자동 저장, 사고 보고서 |
| 로봇끼리 충돌 | 범퍼 | 관련 차량 정지 | 사고 재생으로 진입 순서·예약 확인 | 손상 확인 | 손상 없으면 원격 리셋, 있으면 현장 조치 후 해제 | 사고 보고서, 예약 불일치가 원인이면 구간 봉쇄 |
| 관제 비상정지 | 운영자 명령(사유 필수) | 전체 원격 정지 | 사유 기록, 현장 안전 확인 | — | 해제하면 전체 일시정지로 전환. 재개는 따로, 구역별 순차 | 감사 로그(누가 걸고 누가 풀었는지) |
| 로봇 고장 | state errors FATAL | 차량 자체 정지, 예약 유지(다른 차량 진입 방지), 신규 배정 중단 | 원격 리셋 1회 → 실패하면 작업 재할당·현장 요청 | 수리, 적재물 회수 | 현장 조치 완료 등록 → 자동 모드·위치 확인 | 고장 유형·위치, MTTR |
| 위치 상실 | state positionInitialized = false | 정지, 주문 거부 | 마지막 노드와 대조해 위치 재지정(노드 1 m 안이어야 성공). 실패하면 막힌 작업 재할당 | 원격 조종으로 가까운 노드 0.6 m 안까지 옮기거나, 현장 인원이 옮기고 재위치 추정 후 현장 조치 완료 | 위치 확인 후 자동 전환 | 발생 위치(간선 한가운데 상실은 교차로를 오래 막음) |
| 통신 두절 | 3초 무수신 | 예약 유지. 차량은 받은 구간 끝에서 자체 정지 | AP·전원 확인 요청, 30초 넘으면 작업 재할당 | AP·전원 점검 | 재연결 후 주문 ID·위치 재동기화(자동) | 두절 구간·시간, 통신 감도 추이 |
| 인프라 감지 두절 | 카메라 피드 3초 무수신 | 사람 작업·보행·피킹 구역 전체 사람 감속 | 사각지대 구역 봉쇄 판단 | 카메라·서버 점검 | 추적 수가 평소 수준으로 복귀 | 두절 시간 |
| 고속문 이상 | 요청 후 10초 미개방, 3초 무응답, 고장 신호 | 문을 경로에서 제외, 문 앞 대기 차량 즉시 우회(다른 쓸 수 있는 문이 있을 때만), 이미 문 차선을 예약한 차량은 통과시킴 | 영향 차량 확인. 우회 경로가 없는 작업(남측 문 고장 시 출고)은 재배정 검토. 수리 동안 "사용 중지"(고장 신호가 먼저 풀려도 사용 중지는 남으므로 수리 뒤 반드시 재시도) | 설비 담당: 제어기 전원·통신, 커튼 걸림 | 현장 조치 후 "재시도" → 문이 열림을 보고하면 정상. 사용 중지 문 앞에 차량이 60초 넘게 서 있으면 장시간 정지 알람이 재시도를 안내 | 설비별 고장 이력 |
| 교착 | 대기 관계 순환 2초 유지 | 한 대 재계획 또는 비켜서기 | 30초 안에 안 풀리면: 우선순위 낮은 작업 취소 또는 원격 조종 | 필요하면 한 대 수동 이동 | 자원 해제 확인 | 교착 위치 반복 여부(혼잡 레이어) |
| 장시간 정지 | 대기 사슬의 뿌리가 60초 정지(협업 피킹 존 사람 대기는 180초) | 우회 재탐색 반복 | 원인 확인 후 제거 또는 작업 취소·재할당 | 원인 제거 | 경로 해제 | 같은 지점 반복 시 동선 검토 |
| 배터리 위험 | 10% 미만이고 충전 중 아님 | 30% 미만부터 신규 배정 없이 충전 대기(충전 중이면 60%까지 충전), 7% 미만은 충전기 선점(60% 넘게 찬 대기 차량을 비킴) | 현 작업 유지 가능 여부 판단, 불가하면 재할당 후 충전 | 방전 시 수동 이동 | 충전 | — |
| 원격 조종 인계 | 운영자 명령(확인 필요) | 작업 분리, 0.6초 데드맨, 시뮬레이션 1배속 | 로컬 뷰로 주변을 확인하며 조작 | — | 자동 복귀 명령 | 조종 중 예약 침범은 점유-예약 불일치로 기록 |
| 구역 대피 | 운영자 명령(확인 필요) | 구역 봉쇄 + 구역 안 로봇을 밖으로 이동 | 대피 완료 확인 | 대피 경로 확인 | 봉쇄 해제 | 감사 로그 |

## 4. 비상 계획표

MiR Fleet 문서의 비상 계획표 형식(상황 / 위험 / 예방 조치 / 현장 조치)입니다(R2 B-3).

| 상황 | 위험 | 예방 조치 | 현장 조치 |
|---|---|---|---|
| 관제 서버 정지 | 신규 작업·예약 갱신 중단. 차량은 받은 구간 끝에서 정지 | UPS, 재기동 절차 문서화. 예약은 차량 측 released 구간 밖으로 나가지 않게 설계 | 서버 재기동 → 차량 재연결·재동기화 확인 → 교착·작업 큐 확인 → 순차 재개 |
| 무선망 장애 | 다수 차량 통신 두절, 작업 정체 | AP 이중화, 채널 사용률 감시(60% 초과 시 지연 증가, R2 B-1) | 두절 차량 위치 확인, 필요하면 해당 구역 봉쇄. 복구 후 동기화 확인 |
| 차량 방전 | 통로 한가운데 정지, 뒤 차량 정체 | 30% 미만 신규 배정 중단·충전, 10% 미만 알람, 7% 미만 충전기 선점 | 수동 모드로 가까운 충전기까지 이동하거나 밀어서 회수 |
| 인프라 카메라 두절 | 사각지대 사람을 관제가 모름 | 사람 구역 전체 자동 감속, 감지 피드 감시 | 복구 전까지 사각지대 봉쇄 검토 |
| 고속문 고장 | 남측 문 고장 시 출고 스테이징 접근 불가(단일 장애점) | 문 고장 판정·우회 자동화, 동측 남행 우회로 설계 검토 | 설비 담당 호출, 출고 작업 재배정 또는 대기 |
| 건물 비상(화재 경보) | 대피 동선에 차량 정지 | 구역 대피 명령, 비상정지는 사유 필수·해제 후 자동 재개 없음 | 해당 구역 대피 → 필요하면 전체 비상정지 → 해제 후 구역별 순차 재개 |
| 레이아웃·설정 손상 | 잘못된 경로·속도 | 레이아웃 검증(차종별 강연결)을 기동 시 실행 | 이전 버전으로 되돌리고 재기동 |

## 5. 사고 보고서 양식

사고 기록 탭에서 해당 사고를 선택하면 재생과 요약이 나옵니다. 원자료는 `GET /api/incident/{id}`로 받을 수 있습니다.

```
사고 번호: INC-003          종류: 근접사고 / 사람 접촉 / 충돌        우선순위:
발생 시각:                   확인까지:        해제까지:        종결:
관련 유닛: (로봇, 사람·지게차 추적 ID, 구역)
경위(재생 기준 타임라인):
  -30 s  …
  0 s    …
  +10 s  …
1차 원인:        (예: 사각지대 진입, 보호필드 설정, 예약 불일치, 통신 지연)
근본 원인:
즉시 조치:        (감사 로그의 명령과 시각)
시정 조치:        담당 / 기한 / 상태(열림·진행·종결)
재발 방지 확인:    (같은 지점 근접사고·보호정지 추이)
```

## 6. 교대 인수인계 양식

"인수인계 기록"을 누르면 메모와 함께 아래 요약이 자동으로 저장됩니다(`GET /api/handover`). "현재 상황 요약 받기"는 같은 내용을 텍스트로 내려받습니다.

| 항목 | 내용 |
|---|---|
| 운영 모드 | 정상 / 전체 일시정지 / 비상정지 |
| 활성 알람 | 우선순위 1–3, 상태 포함 |
| 미종결 사고 | 사고 번호·종류·대상 |
| 고장·통신 두절·원격 조종·일시정지 차량 | 목록 |
| 봉쇄 구역·수동 속도 제한 | 목록 |
| 교착 | 진행 중인 순환 |
| 작업 | 대기·진행 수 |
| 지표 | 처리량, 교통 대기 비율, 접촉, 근접사고, 알람률 |
| 메모 | 조치 중인 사항, 주의 구역·로봇, 다음 교대 요청(필수) |

## 7. 훈련

훈련·시나리오 탭(또는 `POST /api/command`)으로 고장을 주입합니다. 명령은 감사 로그에 [훈련]으로 남습니다. 통과 기준은 자동 테스트로도 확인합니다.

| 훈련 | 주입 | 기대 결과 | 자동 테스트 |
|---|---|---|---|
| 로봇 고장 | `drill_fault` (구동부·위치·센서·방전·범퍼, 원격 리셋 가능 여부. 화면에는 범퍼를 뺀 4종) | ROBOT_FAULT, 예약 유지, 원격 리셋 또는 작업 재대기 | `test_fault_requeues_unloaded_task` |
| 통신 두절 | `drill_comms` (1–120 s) | COMMS_LOST, 예약 유지, 받은 구간 끝에서 정지, 복구 후 목적지 도착 | `test_comms_loss_keeps_reservations_and_vehicle_stops_at_base_end` |
| 사람 진입 | `drill_intruder` (구역, 머무는 시간) | 예측 점유로 진입 차단, 사람 구역 감속, 이탈 후 재개 | `test_person_prediction_blocks_then_releases` |
| 고속문 고장 | `drill_door` (JAM·MOTOR·NO_RESPONSE) | FACILITY_FAULT, 다른 문으로 우회, 수리·재시도 후 복귀 | `DoorTests` 9개 |
| 비상정지 | 관제 비상정지 → 해제 | 해제 후 전체 일시정지 유지, 재개는 별도 | `test_fleet_commands_need_confirmation` |
