# 벤치마크

실험 수치는 시드를 고정한 시뮬레이션에서 나왔고 `tools/benchmarks.sh`로 다시 만들 수 있습니다. 결과 JSON(`results/`)에는 실행별 지표, 설정, Python 버전, git 커밋이 기록됩니다. 수요·제원·행동 모델은 현장 데이터로 보정하지 않은 설계 추정치입니다. 결과는 절대 성능 보증이 아니라 대안·대수·가정 사이의 비교와 병목 탐색에 씁니다.

## 1. 방법

| 항목 | 값 |
|---|---|
| 수요 | 측정 전에 정한 설계 기준 수요([SITE.md](SITE.md) 5절). 평균 시간은 입고 트럭 2.4대, 출고 31팔레트, 토트 82건/h. 피크 시간은 3.0대, 39팔레트, 103건/h |
| 피커 가정과 운영 인원 | 토트 103건/h는 피커 6명 × 100 UPH ÷ 주문당 5.83개로 만든 초기 수요 가정. 실제 시나리오의 운영 인원은 표준 7명, 피크 8명이며 목표 수요를 바꾸지 않음 |
| 측정 구간 | 초기 조건의 영향을 줄이려고 30분 워밍업 뒤부터 집계. 워밍업이 정상 상태 도달을 보장하지 않으며, 처리량과 사이클 시간은 측정 구간 전체 평균 |
| 실행 길이 | 교대 시나리오 8시간, 대수 산정 1시간, 운영 방식·민감도 2시간, 알고리즘 격자 1시간(워밍업 10분) |
| 시드 | 시나리오별 2~4개, 그 밖의 비교는 2~3개. 표는 평균 ± 95% 신뢰구간 반폭(Student t). 결측값은 제외하며 일부 실행만 유효한 지표는 유효 표본 수를 함께 표시. 유효 표본이 1개면 평균만 표시 |
| 운영자 | 가상 운영자 사용. 10~40초 뒤 알람을 확인하고 SOP에 따라 원격 리셋·재할당·현장 조치(4~8분)·문 사용 중지를 수행 |
| 전략 | 별도 표기가 없으면 `locks+resolve` |
| 실행 수·병렬 수 | 총 148회. 같은 설정의 재현 대조 5쌍 포함. 모든 단계를 4개씩 병렬 실행 |
| 재현 | `bash tools/benchmarks.sh` 뒤에 `sizing`, `shift`, `methods`, `sensitivity`, `grid` 중 하나를 지정. 결과 JSON의 `git` 필드로 실행 커밋과 작업 트리 상태 확인 |

실행 명령은 다음과 같습니다. 결과 파일의 커밋과 Python 버전을 함께 확인합니다.

```bash
cd ~/fleet-control-tower
for fct_stage in sizing shift methods sensitivity grid; do
  WORKERS=4 bash tools/benchmarks.sh "$fct_stage" || break
done
```

시드는 같은 조건을 반복할 때 각 난수 스트림의 초기 상태를 재현하는 값입니다. 차량·사람 수나 전략이 달라지면 난수 소비 순서와 상호작용도 달라질 수 있으므로, 서로 다른 조건의 모든 도착·고장·사람 행동이 사건별로 같은 시계열을 따른다고 보장하지는 않습니다. 결과의 재현 범위는 같은 코드, Python과 OS 환경, 프로세스 구성에 한정되며 모든 환경에서 비트 단위로 같은 결과가 나온다고 보장하지 않습니다. 시뮬레이션 가속은 최적화 전후 6개 실행에서 KPI·이벤트·알람·위치 해시를 대조한 뒤 적용했습니다.

## 2. 지표

| 지표 | 정의 |
|---|---|
| 적치·출고·토트/h | 측정 구간에 끝난 팔레트 랙 적치, 수동 지게차의 출고 트럭 적재, 토트 주문 수를 시간으로 나눈 값 |
| AGF 이동/대·h | AGF가 끝낸 적치·출고 이동 수 ÷ AGF 대수 ÷ 측정 시간 |
| 토트/대·h | 끝난 토트 주문 수 ÷ 토트 AMR 대수 ÷ 측정 시간 |
| 피커 UPH·LPH | 피커 1인당 시간당 품목 수와 모델의 병합 피킹 액션 수. 공개 사례의 주문 라인과 같은 단위가 아님 |
| 가동률 | 측정 구간 평균으로 차량이 작업을 가진 시간의 비율 |
| 교통 대기 비율 | 작업을 가진 시간 중 예약 대기나 차단으로 선 비율. 보호정지와 작업 동작은 제외 |
| 교착 / 자동 해소 | 구성원 모두의 대기 시간이 확인 기준(현재 2초) 이상인 순환이 새로 등록된 횟수 / 해당 등록에 해소 동작이 기록되고 이후 감지 그래프에서 사라질 때 증가한 횟수. 같은 사슬도 감지 관계가 끊겼다가 다시 나타나면 재등록됨 |
| 예약 자료 검사(`lock_problems`) | 종료 시 예약의 자원별·소유자별 색인이 일치하는지, 중복 항목이 있는지 검사한 문제 수 |
| 점유·예약 불일치(`mismatch`) | 수동 모드를 제외한 차량의 보고 점유 구간이 자기 예약에는 없고 다른 유닛이 예약한 상태가 1.5초 이상 이어져, 불일치 알람과 해당 차량의 일시정지를 새로 발생시킨 횟수. 종료 시 예약 자료 검사와 별도로 봄 |
| 접촉·근접사고·간격 위반·근접 통과 | 측정 구간의 발생 건수이며 시간당 값이 아님. 평가기의 실제 위치와 차체 모양 기준. 정의는 [SAFETY.md](SAFETY.md) 5절 |
| 관제 근접사고 알림 | 추적값으로 관제가 판정한 수. 평가기 결과와 비교해 추적 품질 확인 |
| 알람/h | 4순위 알림을 뺀 새 알람 수. ISA-18.2 조사 기준은 운영 위치당 6~12건/h([research/01](research/01_standards_traffic_safety_ops.md) §4.1) |
| MTTA·MTTR | 알람 발생부터 확인까지의 시간 / 고장 발생부터 해제까지의 시간 |
| 대기 작업(`queued`) | 공정에서 방출한 작업 중 상태가 `QUEUED`인 수. 입고·출고·토트 작업을 함께 세며 실행 중인 `ACTIVE` 작업은 제외. 토트 주문은 여러 개가 한 작업으로 묶일 수 있음 |
| 출고 백로그(`site_out_backlog`) | 팔레트나 출고 스테이징 자리를 확보하지 못해 아직 운송 작업으로 방출하지 않은 출고 주문 수. 이미 방출한 작업, 운송 중·스테이징·트럭 적재 대기는 제외하므로 0이어도 전체 출고 완료를 뜻하지 않음 |
| 토트 백로그(`site_tote_backlog`) | 아직 묶어서 AMR 작업으로 방출하지 않은 개별 토트 주문 수. 이미 방출했거나 실행 중인 작업은 제외 |
| 입고·출고 스테이징 | 각 스테이징 레인에 실제로 놓인 팔레트 수. 운송 중이거나 자리를 예약한 팔레트는 제외. 종료 시점의 재고이며 시간당 처리량이나 시간 평균이 아님 |

워밍업이 끝나면 측정용 카운터와 집계 상태를 초기화하고, 미처리 주문·진행 중 작업·스테이징을 포함한 운영 상태는 유지합니다. 설계 수요는 확률적 도착률의 입력 평균입니다. 한 실행의 처리량이 그 평균보다 낮다는 사실만으로 실제 도착 수요의 미충족을 확정하지 않습니다. 원시 결과에는 전체 출고 요청 수가 저장되지 않으므로 출고 수요 충족률을 이 JSON만으로 계산할 수 없습니다.

선정안: 이번 2시드·1시간 결과로 확정 대수를 고르지 않았습니다. 기본 규칙에서 토트 AMR 14대와 16대의 토트 처리량은 평균 100건/h로 같았습니다. 16대는 종료 대기 작업이 적었지만 이동 중 접촉이 남아, 증차의 효과를 한 지표로 판단할 수 없습니다.

판정 근거: AGF 10대·토트 AMR 16대·피커 7명은 적치 36·39, 출고 38·35, 토트 108·92건/h였습니다. 같은 조건의 AGF를 11대로 늘린 시드 1은 적치 3·출고 15·토트 95건/h, 종료 대기 작업 40건, 방출 전 출고 주문 12건으로 저하했습니다. 교착 등록 159회·자동 해소 0회·종료 활성 교착 0회가 함께 관측됐으므로 종료 교착 수만으로 정상이라고 볼 수 없습니다.

AGF 10대·피커 7명을 고정한 토트 AMR 14대는 토트 106·94건/h, 종료 대기 작업 18·12건, 이동 중 접촉 0·0건이었습니다. 16대는 토트 108·92건/h, 대기 작업 3·6건, 이동 중 접촉 1·4건입니다. 최초에 무너졌던 AMR 10대 시드 1·12대 시드 2·14대 시드 2는 적치/출고/토트가 각각 12/46/82, 55/33/90, 41/36/94건/h이며 접촉·교착·점유와 예약 불일치는 모두 0입니다. 원래 정체에서 작업 처리는 회복했지만 토트 103건/h 목표를 모두 달성한 것은 아닙니다.

피킹 구역의 관제 사람 감속을 제거하고 차량 보호필드·측면 경고를 유지한 `vehicle` 변형은 AMR 12대에서 토트 106·107건/h, 16대에서 105·109건/h였습니다. 피커 이동 규칙을 바꾼 시험이 아니며 기본 대수 조건과 운영 방식이 다릅니다. 토트 작업 방출 상한을 해제한 `agf10-nocap`은 110·92건/h로 시드 차이가 남았습니다. 모든 28회의 종료 예약 자료 검사와 점유·예약 불일치는 0이지만, 일부 조건의 접촉과 대기 작업은 남았습니다. 처리율과 확률 도착률의 평균을 비교한 결과이며, 실제 출고 요청 총수가 JSON에 없어 전체 수요 충족률을 계산할 수는 없습니다.

설계 피크 토트 목표는 103건/h입니다. 시드별 처리량이나 95% 신뢰구간이 목표에 못 미치면 그 격차를 표와 해석에 그대로 남깁니다. 대수를 늘려도 처리량이 늘지 않거나 대기 비율이 커지는 조건은 용량 확대안으로 채택하지 않습니다.

## 8. 해석할 때의 한계

- 결과는 규칙 기반 사람·지게차 모델과 가정한 수요·제원·고장률에서 나옵니다. 현장 성능 보증값이 아닙니다.
- 워밍업은 초기 조건의 영향을 줄이지만 정상 상태를 보장하지 않습니다. 종료 시 백로그와 시계열 추세를 함께 봐야 합니다.
- 교착 지표 해석: 대수 산정의 AGF 11대 시드 1은 교착 등록 159회·자동 해소 0회·종료 활성 교착 0회여도 적치 3건/h와 종료 대기 작업 40건으로 저하했습니다. 등록 횟수는 서로 다른 교착의 수가 아니며, 종료 그래프에서 순환이 사라졌다는 사실은 물리적 정체가 풀렸다는 뜻이 아닙니다. 이전 `d50e022` 진단에서 같은 수치의 반복 등록을 추적했지만 이번 커밋의 내부 사건을 새로 추적한 것은 아니므로 동일한 차량 사슬이나 원인으로 확정하지 않습니다.
- 시드가 2~4개인 조건은 드문 트럭 도착, 고장, 통신 두절의 불확실성을 좁게 추정하기 어렵습니다. 95% 신뢰구간이 넓으면 순위를 단정하지 않습니다.
- 설계 피크 토트 103건/h는 시드에 따라 달성하지 못할 수 있습니다. 평균만으로 충족을 주장하지 않고 시드별 값과 백로그를 함께 표시합니다.
- MTTA는 가상 운영자의 응답 분포를 입력으로 쓴 결과이며 사람 운영자의 측정값이 아닙니다.
- 평가기 안전 지표는 시뮬레이션의 실제 위치를 쓰고, 관제 알림은 지연과 오차가 있는 추적값을 씁니다. 둘의 차이는 추적 품질을 보여 주지만 실제 사고율을 예측하지 않습니다.
- 사람 움직임이 시작된 뒤 관측 이력이 쌓이기 전까지 사람 예측이 정지로 남을 수 있습니다. 관제는 차량 탑재 안전 기능을 대신하지 않습니다.
- 공개 생산성 자료의 사람 시간과 차량 시간, 팔레트·품목·주문 라인 정의가 서로 달라 수치 우열을 판정할 수 없습니다.
- 결과 커밋이 `+dirty`이거나 단계별 커밋이 다르면 한 묶음의 최종 근거로 쓰지 않습니다.
