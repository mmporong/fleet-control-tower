# 벤치마크

모든 수치는 시드를 고정한 시뮬레이션에서 나왔고 명령 한 줄로 다시 만들 수 있습니다. 결과 JSON(`results/`)에는 실행마다 전체 지표, 설정, 파이썬 버전, git 커밋이 기록됩니다. 채용 공고가 요구한 "대수 증가에 따른 처리량·대기·교착 곡선"과 "결함 주입 시나리오별 통과 기준"(research/02 A-5 #3·#8, C-1 지표 표)을 보이는 것이 목적입니다.

## 1. 방법

| 항목 | 값 |
|---|---|
| 실행 길이 | 시뮬레이션 1시간(3,600 s), 시작 직후부터 집계 |
| 시드 | DC 1–6, AMR 대수 확장과 격자 1–3(표는 평균 ± 표준편차) |
| 운영자 | 가상 운영자 켬: 10–40 s 뒤 알람 확인, SOP대로 원격 리셋·재할당·현장 조치(4–8분)·문 사용 중지 |
| 전략 | 별도 표기 없으면 `locks+resolve` |
| 커밋 | DC 용량 측정 `83b3923`, 나머지 `fcc52ec`. 두 커밋 사이 변경은 비상정지 사유 필수와 서버 기동 시 레이아웃 검증뿐이라 시뮬레이션 결과는 같음 |

```bash
cd ~/fleet-control-tower
D="python3 -m fleet.bench --seeds 1,2,3,4,5,6 --duration 3600 --workers 8"
$D --scenario standard --variants '[{"label":"standard"},{"label":"saturated","scenario_overrides":{"trucks_h":6,"out_pallets_h":45,"tote_orders_h":135}}]' --out results/dc_capacity.json
$D --scenario standard --strategies none,locks --out results/dc_strategies_partial.json
for s in standard peak crowded faults night; do $D --scenario $s --out results/dc_scenario_$s.json; done
python3 -m fleet.bench --seeds 1,2,3 --duration 3600 --scenario standard \
  --variants '[{"label":"amr08","scenario_overrides":{"amr":8,"tote_orders_h":120}}, ... "amr24"]' --out results/dc_amr_sweep.json
G="python3 -m fleet.bench --seeds 1,2,3 --duration 3600 --workers 6"
$G --scenario grid-deadlock --strategies none,locks,locks+resolve --out results/grid_deadlock_strategies.json
$G --scenario grid-night --robots 5,10,20,30,40 --out results/grid_fleet_size.json
$G --scenario grid-night --robots 5,10,20,30,40,50 --variants '[{"label":"saturated-noext","scenario_overrides":{"rate_per_h":600,"external":0}}]' --out results/grid_fleet_size_saturated_noext.json
$G --scenario grid-night --robots 10,20,30,40,50 --variants '[{"label":"saturated","scenario_overrides":{"rate_per_h":600}}]' --out results/grid_fleet_size_saturated.json
$G --scenario grid --strategies none,locks+resolve --out results/grid_mixed.json
```

같은 설정·시드로 따로 돌린 결과는 모든 지표가 완전히 같습니다(용량 측정의 표준 조건, 표준 시나리오, 전략 비교의 예약+교착 해소를 대조해 확인). 표준편차가 큰 지표는 모델이 결정적이지 않아서가 아니라 시드마다 트럭 도착 수(시간당 2.2대 포아송, 1시간에 2–6대)와 무작위 고장 위치가 다르기 때문입니다.

## 2. 지표

| 지표 | 정의 |
|---|---|
| 처리량 | 최근 1시간 안에 끝난 작업 수(작업/시간). DC는 적치·출고·토트로 나눠 표시 |
| 교통 대기 비율 | 작업을 가진 차량의 시간 가운데 예약 대기(다른 로봇)나 차단(사람·지게차·타사 로봇·문·봉쇄 구역)으로 서 있던 비율. 보호정지·작업 동작 시간은 제외 |
| 교착 / 해소 | 대기 관계 순환이 2초 넘게 유지된 횟수 / 자동으로 풀린 횟수. 차이는 운영자 조치가 필요했던 건 |
| 접촉 | 평가기(실제 위치·차체 모양) 기준으로 차량이 움직이는 중에 다른 유닛과 닿은 횟수 |
| 근접사고 | 평가기 기준 ISO 3691-4 감속 조건 위반: 0.35 m/s 초과에서 간격 0.3 m 미만, 또는 0.1 m/s 초과에서 0.1 m 미만 |
| 알람/시간 | 새로 발생한 알람 수(4등급 알림 제외). ISA-18.2 권고 목표는 운영 위치당 10분에 1–2건, 곧 시간당 6–12건(research/01 §4.1) |
| MTTA | 알람 발생부터 확인까지(가상 운영자, 가정한 응답 분포 10–40 s를 따름) |
| MTTR | 고장 발생부터 해제까지 |
| 입고→적치 | 트럭에서 내린 팔레트가 랙에 들어갈 때까지(dock-to-stock) |
| 대기 작업 | 1시간 뒤 배정되지 않은 작업 수. 늘어나면 수요가 용량을 넘은 것 |

### 3.3 시나리오

- 장애 훈련은 로봇마다 평균 1시간에 한 번 고장·통신 두절이 나고 메시지 2%가 손실되며 고속문도 고장 납니다. 처리량은 표준보다 약 30% 낮고 알람은 시간당 100건을 넘지만, 이동 중 접촉 0, 점유-예약 불일치 0으로 안전 불변식은 유지됩니다. MTTA 약 20초는 가상 운영자의 응답 분포 가정(10–40초)에서 나온 값입니다.

## 6. 해석할 때 주의할 점

- 결과는 규칙 기반 사람·지게차 모델과 가정한 제원·수요에서 나온 값입니다. 절대 수치보다 전략·대수·시나리오 사이의 비교가 의미 있습니다.
- 1시간 실행에 3–6개 시드라 트럭 도착·고장처럼 드문 사건의 편차가 큽니다. 표의 ± 는 시드 간 표준편차입니다.
- MTTA는 가상 운영자의 응답 분포 가정에서 나온 값으로, 사람 운영자의 성능을 뜻하지 않습니다.
- 관제가 추정한 근접사고(`near_miss_fms`)는 추적 불확실성을 보수적으로 두어 평가기 기준보다 많이 잡힙니다. 표의 근접사고는 평가기 기준입니다.
