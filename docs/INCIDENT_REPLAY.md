# AGF 순환 정체 조사와 기록 재생

회전 직전의 보호영역이 예약에서 빠지는 문제를 재현했습니다. 예약 범위를 모든 방향으로 넓힌 첫 수정은 다른 조건에서 처리량을 무너뜨려 기각했습니다. 현재 작업 브랜치에는 실제 차체 원과 전방 보호영역이 겹치는 노드만 예약하는 실험 후보를 보존했습니다. 네 조건의 실험까지 완료했으며, 전체 성능 검증과 공개 배포는 보류했습니다.

## 무엇이 막혔나

기준 소스 `d7cacc9b9b234958f8292866da4b651c75a1b1c1`의 AGF 11대·seed 1에서 `t=2778.7 s`에 `AGF-01 → AGF-03 → AGF-06 → AGF-09 → AGF-01` 순환 대기가 기록됐습니다. AGF-01은 회전 직전에 AGF-03을 정지 보호필드로 감지해 멈췄지만, 이미 다음 구간의 예약을 잡고 있었습니다. 뒤의 세 차량도 다음 차량이 가진 노드를 기다려 고리가 닫혔습니다.

기존 회전 예약 반경은 대표 교차점에서 약 `3.048 m`였고, 회전 노드와 대기 노드의 중심 거리는 `3.10 m`였습니다. 보호필드가 감지하는 차량이 서 있는 대기 노드가 예약에서 빠졌습니다. 교착 등록 159회는 독립된 사건 159개를 뜻하지 않습니다. 같은 대기 사슬도 감지 관계가 잠시 끊겼다가 다시 나타나면 새로 등록되며, 종료 시 활성 교착이 0이라는 이유만으로 회복을 판단할 수 없습니다.

## 기각한 수정

첫 후보 `a08423a`는 회전 예약 여유를 `0.2 m`에서 `0.51 m`로 늘렸습니다. 대표 사례의 출고는 15건/h에서 37건/h로 늘었지만, 대수 산정 28개 조건에서 광범위한 정체가 생겼습니다. AGF 10대·seed 1의 출고는 38건/h에서 3건/h로, seed 2는 35건/h에서 0건/h로 떨어졌습니다. 먼 회전 구간을 일찍 예약한 차량이 수동 지게차에 막힌 동안, 뒤의 차량도 그 예약 때문에 움직이지 못했습니다.

진입 방향과 예약 시점을 제한한 다음 후보는 측면 차체를 충분히 포함하지 못했습니다. 이를 큰 원으로 보완하자 과예약이 다시 발생했습니다. 이 후보들의 결과와 기각한 28개 조건은 [실험 원본](../results/experiments/turn-reservation-20261025/)에 따로 보존했습니다. 기존 전체 벤치마크 결과를 새 후보의 결과로 덮어쓰지 않았습니다.

## 마지막 실험 후보

물리적 회전 여유 `0.2 m`와 기존 stub 진입 규칙은 유지합니다. 전방 보호영역에는 시뮬레이터와 같은 차체 원을 사용하고, 해당 노드에서 차량 클래스가 허용되는 진입·진출 방향을 검사합니다. 미래 회전은 차량이 도착 처리되기 직전의 위치를, 현재 노드에서 시작하는 회전은 관측 위치와 방향을 사용합니다. 추가 보호영역은 다음 통과 구간과 한꺼번에 예약하며, 먼 회전의 추가 예약은 차량이 가까워질 때까지 미룹니다.

모든 실험은 `standard`, `locks+resolve`, 준비 30분·측정 1시간, 트럭 3대/h·출고 39팔레트/h·토트 103주문/h·피커 7명 조건입니다. 아래 값은 짧은 3D 재생 구간이 아닌 전체 측정 구간의 결과입니다.

| 조건 | 적치 기준→후보(건/h) | 출고 기준→후보(건/h) | 토트 기준→후보(건/h) | 접촉 기준→후보 | 이동 중 접촉 기준→후보 |
|---|---:|---:|---:|---:|---:|
| AGF 11·AMR 16·seed 1 | 3→36 | 15→35 | 95→104 | 6→1 | 0→1 |
| AGF 10·AMR 16·seed 1 | 36→33 | 38→36 | 108→107 | 1→1 | 1→0 |
| AGF 10·AMR 16·seed 2 | 39→39 | 35→39 | 92→92 | 4→5 | 4→0 |
| AGF 10·AMR 10·seed 1 | 12→12 | 46→46 | 82→82 | 0→2 | 0→1 |

후보의 네 조건 모두 교착 등록·예약 자료 문제·위치와 예약 불일치는 0이었습니다. 대표 정체의 처리량은 회복됐지만, 일부 조건의 처리량은 줄었고 새 이동 중 접촉도 발생했습니다. 정체 해결이나 안전 개선이 전체 조건에서 입증됐다고 판단하지 않습니다.

AGF 11·seed 1과 AMR 10·seed 1 기준값은 `d7cacc9` 재실행에서 확인했습니다. AGF 10·AMR 16의 두 기준값은 기존 `07ac6b5` 대수 산정 결과입니다. 두 소스 사이의 `fleet/` 변경은 3D 서버와 수동 지게차 동작 표시였으며, 제어·차량 동작 코드는 같았습니다. 별도로 재실행한 기준의 피크 8시간·3시드 결과도 과거 KPI와 일치했습니다. 이는 마지막 후보의 8시간 검증을 뜻하지 않습니다.

마지막 후보 원본은 [candidate-exact-circles-4jobs.json](../results/experiments/turn-reservation-20261025/candidate-exact-circles-4jobs.json)입니다. 커밋 전 실행이므로 `git` 값은 `72f95e3+dirty`이고, 변경 파일별 SHA-256과 실행 전후 동일 여부를 함께 기록했습니다. 같은 소스는 로컬 커밋 `af16870`에 보존했습니다. 네 조건은 배포 판단을 대신하지 않으며, 대수 산정 28개를 포함한 전체 실험 148개를 새 후보로 재실행하지 않았습니다.

## 기록 재생 기능과 공개 상태

로컬 3D 화면에는 기록 선택, 0.5~8배속, 시간 이동, 주요 사건 이동, 차량별 대기 원인·예약 자원·관계선, 동일 조건의 결과 비교를 구현했습니다. 비교표는 증가·감소·동일과 지표별 개선·악화를 구분합니다. 서버의 실시간 사건 형식도 지원하며, 화면 정지는 시뮬레이터 제어 명령을 보내지 않습니다.

기준 정체 기록의 범위는 `t=2700~2880 s`입니다. 최초 측정 교착 `t=2778.7 s` 다음 프레임인 `t=2779.0 s`에서 AGF-06이 AGF-09의 노드를 기다리는 관계를 확인할 수 있습니다. 기존에 생성한 수정 후 기록은 기각한 `a08423a` 소스의 파일이므로 공개 개선 자료로 사용하지 않습니다. 마지막 후보의 재촬영·GIF·포트폴리오 반영은 수행하지 않았습니다.

기준 기록은 다음 명령으로 재현할 수 있습니다.

```bash
cd ~/fleet-control-tower
FLEET_REPLAY_DIR="$(mktemp -d)"
git worktree add --detach "$FLEET_REPLAY_DIR/baseline" d7cacc9b9b234958f8292866da4b651c75a1b1c1
PYTHONPATH="$FLEET_REPLAY_DIR/baseline" \
  python3 tools/export_3d_replay.py \
  --job tools/replay/agf11-seed1.json \
  --start 2700 --duration 180 --sample 0.5 --rate 8 \
  --out "$FLEET_REPLAY_DIR/before.json"
```

내보내기 도구는 저장 구간이 끝난 뒤에도 전체 실험의 측정 종료까지 진행합니다. `frames`는 3분의 좌표·상태이고, `measurement.summary`는 준비 구간을 제외한 1시간 결과입니다. 소스 커밋과 파일 해시도 기록합니다.

## 적용 한계

차체 형상과 보호필드 상수는 이 저장소의 기본 AGF·AMR 시뮬레이터 기준입니다. factsheet에서 임의의 보호필드 설정을 받아 계산하지 않으며, 커스텀 차량·지도와 실차의 정지 거리·보호필드·현장 동선을 검증한 결과가 아닙니다. 현장 적용 범위와 안전 책임은 [안전 개념](SAFETY.md)을 따릅니다.
