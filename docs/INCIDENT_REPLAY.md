# AGF 순환 정체 재현과 3D 비교

이 사례는 AGF 11대 조건에서 처리량이 급격히 떨어진 한 실행을 같은 입력으로 다시 돌려 원인을 찾고, 수정 전후를 3D 기록으로 비교한 결과입니다. 기준 소스는 `d7cacc9b9b234958f8292866da4b651c75a1b1c1`, 수정 후보는 `a08423a6358ca4788ab46fcf376a446a73a8cb1f`입니다.

## 무엇이 막혔나

측정 구간의 `t=2778.7 s`에 `AGF-01 → AGF-03 → AGF-06 → AGF-09 → AGF-01` 순환 대기가 기록됐습니다. AGF-01은 회전 직전에 AGF-03을 정지 보호필드로 감지해 멈췄지만, 이미 다음 구간의 예약을 잡고 있었습니다. 뒤의 세 차량도 다음 차량이 가진 노드를 기다려 고리가 닫혔습니다.

원인은 회전할 때 미리 예약하는 범위가 차량의 정지 보호필드보다 작았던 데 있습니다. 기존 계산은 대표 교차점에서 약 `3.048 m`까지 포함했지만, 회전 노드와 대기 노드의 중심 거리는 `3.10 m`였습니다. 약 `5.2 cm` 차이로 대기 노드가 예약 범위에서 빠졌습니다. 회전 예약 여유를 `0.2 m`에서 `0.51 m`로 바꾸면 예약 반경이 약 `3.358 m`가 되어 기본 AGF의 정지 보호필드 범위 `3.35 m`를 포함합니다.

예약을 빼앗거나 차량의 보호정지를 해제하는 방식은 쓰지 않았습니다. 회전에 들어가기 전에 필요한 공간을 한꺼번에 확보하고, 확보할 수 없으면 진입을 기다립니다.

## 같은 조건에서 확인한 변화

두 실행은 `standard`, `locks+resolve`, seed `1`과 같은 부하·자원 설정을 사용했습니다. 30분 동안 워밍업한 뒤 1시간을 측정했습니다.

| 지표 | 기준 | 수정 후보 |
|---|---:|---:|
| 입고 적치 | 3건/h | 41건/h |
| 출고 | 15건/h | 37건/h |
| 토트 | 95건/h | 106건/h |
| 종료 대기 작업 | 40건 | 13건 |
| 교통 대기 비율 | 0.356 | 0.154 |
| 교착 등록 | 159회 | 0회 |
| 접촉 | 6건 | 0건 |

기준 실행의 교착 159회는 서로 다른 교착이 159개 있었다는 뜻이 아닙니다. 같은 물리적 대기 사슬도 감지 관계가 잠시 끊겼다가 다시 나타나면 새로 등록됩니다. 종료 시 활성 교착이 0이더라도 실행 중 순환 정체가 해소됐다고 볼 수 없는 이유입니다. 수정 후보에서는 같은 조건의 교착 등록과 접촉이 모두 0이었습니다.

이 표는 대표 단일 시드의 전후 비교입니다. 다른 시드와 차량 대수에서도 같은 결과가 난다고 일반화하거나, 현장 안전과 최종 용량을 입증하는 수치로 사용할 수 없습니다.

## 3D 기록에서 확인할 것

공개 3D 비교는 절대 시각 `t=2700~2880 s`를 저장합니다. 기준 실행에서 처음 측정된 순환 정체의 앞뒤 3분을 볼 수 있도록 잡은 구간입니다. 개선 전·후 비교표의 수치는 이 3분만 집계한 값이 아니라, 워밍업 뒤 전체 1시간 측정 결과입니다.

타임라인을 `t=2778.7 s` 부근으로 옮기면 차량별 대기 원인과 상대, 예약 자원을 볼 수 있습니다. 다음 프레임은 `t=2779.0 s`이며, AGF-06이 AGF-09가 가진 노드를 기다리는 관계가 표시됩니다. 재생 기록은 원인 조사용 보기이며 제어 명령을 보내지 않습니다.

## 같은 입력으로 기록 만들기

실험 입력은 [`tools/replay/agf11-seed1.json`](../tools/replay/agf11-seed1.json)에 고정했습니다. 아래 명령은 기준과 수정 후보를 분리된 Git worktree에 체크아웃한 뒤, 현재 저장소의 내보내기 도구에 각 소스 경로를 지정합니다.

```bash
cd ~/fleet-control-tower
FLEET_REPLAY_DIR="$(mktemp -d)"
git worktree add --detach "$FLEET_REPLAY_DIR/baseline" d7cacc9b9b234958f8292866da4b651c75a1b1c1
git worktree add --detach "$FLEET_REPLAY_DIR/candidate" a08423a6358ca4788ab46fcf376a446a73a8cb1f

PYTHONPATH="$FLEET_REPLAY_DIR/baseline" \
  python3 tools/export_3d_replay.py \
  --job tools/replay/agf11-seed1.json \
  --start 2700 --duration 180 --sample 0.5 --rate 8 \
  --out "$FLEET_REPLAY_DIR/before.json"

PYTHONPATH="$FLEET_REPLAY_DIR/candidate" \
  python3 tools/export_3d_replay.py \
  --job tools/replay/agf11-seed1.json \
  --start 2700 --duration 180 --sample 0.5 --rate 8 \
  --out "$FLEET_REPLAY_DIR/after.json"
```

내보내기 도구는 3분 구간의 프레임을 저장한 뒤에도 시뮬레이션을 측정 종료 시각까지 진행합니다. JSON의 `frames`는 `2700~2880 s`, `measurement.summary`는 워밍업 뒤 1시간 전체 결과입니다. `source.commit`, `source.dirty`, 소스 파일 해시도 함께 저장하므로 어떤 코드로 만든 기록인지 확인할 수 있습니다.

## 적용 범위

`0.51 m` 여유는 이 저장소의 기본 AGF와 AMR 차체 크기, 기본 정지 보호필드와 보호정지 해제 히스테리시스를 기준으로 정했습니다. 차량별 `field_base`나 `field_gain`을 재정의한 구성의 상한을 관제가 자동으로 받아 계산하지는 않습니다. 보호필드 설정을 바꾸면 회전 예약 범위를 다시 검토해야 합니다.

이 결과는 시뮬레이션의 대표 정체를 설명하는 재현 사례입니다. 실제 차량의 정지 거리, 보호필드와 현장 동선을 검증한 자료는 아닙니다. 현장 적용 범위와 안전 책임은 [안전 개념](SAFETY.md)을 따릅니다.
